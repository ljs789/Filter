# Mini NPU Simulator

입력된 패턴과 필터를 같은 위치끼리 곱하고 모두 더하는 **MAC(Multiply-Accumulate) 연산**으로
패턴이 십자가(Cross)인지 X인지 판정하는 Python 콘솔 프로그램입니다.
NumPy 같은 외부 라이브러리 없이 표준 라이브러리(`json`, `os`, `sys`, `time`)만 사용합니다.

## 1. 실행 방법

```bash
python main.py
```

- Python 3.8 이상에서 동작합니다.
- 실행하면 모드를 고릅니다.
  - `1` : 사용자 입력 (3x3). 필터 A, B와 패턴을 한 줄에 숫자 3개씩(공백 구분) 입력합니다.
  - `2` : data.json 분석. `main.py`와 **같은 폴더**의 `data.json`을 읽어 일괄 판정합니다.
  - `3` : 패턴 생성기 (보너스). 홀수 N을 넣으면 NxN Cross/X 패턴을 만들어 판정과 성능을 보여줍니다.
- 다른 JSON 파일로 모드 2를 시험하려면 파일 경로를 함께 적습니다.

```bash
python main.py test_error_data.json   # 의도적 오류 케이스 모음
```

## 2. 구현 요약

### 데이터 구조
- 패턴과 필터는 NxN **2차원 리스트**(`list` 안의 `list`)로 저장합니다. `matrix[행][열]`로 특정 위치 값을 읽고 씁니다.
- 3x3, 5x5, 13x13, 25x25를 포함해 어떤 N이든 같은 코드로 처리합니다.

### MAC 연산 (`mac`)
- 이중 `for`문으로 모든 `(i, j)` 위치에서 `pattern[i][j] * filter[i][j]`를 계산해 `total`에 누적하고 float로 반환합니다.
- 곱셈과 덧셈이 정확히 N x N = N^2 번 일어납니다.

### 라벨 정규화 (`normalize_label`)
- 프로그램 내부에서는 표준 라벨 `Cross`, `X` 두 가지만 씁니다.
- 입력 값을 공백 제거 후 소문자로 바꾼 뒤 변환표로 바꿉니다.
  - expected: `'+'` → `Cross`, `'x'` → `X`
  - filter 키: `'cross'` → `Cross`, `'x'` → `X`
  - 대소문자가 달라도(`'X'`, `'Cross'`) 같은 라벨로 처리됩니다.
- 출력과 PASS/FAIL 비교는 모두 표준 라벨 기준입니다. 변환표에 없는 값(예: `'circle'`)은 해당 케이스만 FAIL로 처리합니다.

### 동점 처리 정책 (epsilon)
- `abs(score_a - score_b) < 1e-9` 이면 동점으로 보고 `UNDECIDED`(모드 1에서는 "판정 불가")로 판정합니다.
- 동점이 아니면 큰 쪽을 고릅니다. 모드 2에서 A는 Cross 필터, B는 X 필터입니다.
- `UNDECIDED`는 어떤 expected와도 같지 않으므로 FAIL로 처리됩니다.

### 스키마 검증 (모드 2)
- 패턴 키 `size_{N}_{idx}`에서 `_`로 잘라 N을 꺼내고, `size_N` 필터를 선택합니다.
- 필터와 패턴이 NxN 숫자 배열인지 검사합니다(행 수, 각 행의 열 수, 값의 타입).
- 문제가 있으면 예외로 멈추지 않고 **그 케이스만 FAIL**로 기록한 뒤 다음 케이스로 넘어갑니다.

### 성능 측정
- `time.perf_counter()`로 `mac()` 호출 구간만 잽니다(입력, 출력, 파일 읽기 시간 제외).
- 워밍업 1회 후 10회 반복한 총 시간을 10으로 나눠 1회 평균(ms)을 구합니다.
- 크기마다 같은 종류의 입력(생성한 십자가 패턴)을 써서 크기의 영향만 비교합니다.

### 3-2. FAIL 원인 분석

실패한 3개 케이스는 모두 **수치 비교 문제**이며, 데이터/스키마 문제나 로직 문제가 아닙니다.

1. **데이터/스키마 문제가 아님**: 세 케이스 모두 키에서 N을 정상 추출했고, 필터와 패턴이 NxN 크기 검증을 통과했으며, expected 라벨(`'x'`, `'+'`)도 정상적으로 정규화되었습니다.
2. **로직 문제가 아님**: 같은 MAC 함수가 나머지 3개 케이스(점수 차이가 큰 경우)를 모두 맞혔습니다.
3. **원인은 수학적 동점**: 필터 값을 손으로 계산하면 두 점수가 정확히 같습니다.
   - size_5_1: Cross 필터 중앙값 0.9 vs X 필터 0.1 x 9칸 = 0.9
   - size_13_2: Cross 필터 0.3 x 25칸 = 7.5 vs X 필터 중앙값 7.5
   - size_25_1: Cross 필터 중앙값 4.9 vs X 필터 0.1 x 49칸 = 4.9
4. **부동소수점 오차**: 컴퓨터는 0.1, 0.3 같은 소수를 2진수로 정확히 표현하지 못해서, 여러 번 더하면 `0.8999999999999999`처럼 아주 작은 오차(약 1e-16 ~ 3e-15)가 생깁니다.
5. **epsilon이 없었다면**: `>`로만 비교했을 때 size_5_1은 Cross, size_13_2는 X, size_25_1은 Cross로 판정됩니다. 즉 의미 없는 오차가 결과를 정하고, "X여야 하는데 Cross"라는 엉뚱한 실패가 나와 로직 버그로 오해하게 됩니다.
6. **epsilon 정책 적용 결과**: 차이가 1e-9보다 작으므로 동점(UNDECIDED)으로 정확히 판정했고, 과제의 동점 규칙에 따라 FAIL로 처리했습니다. 이 FAIL은 "두 필터가 이 패턴을 구분하지 못한다"는 올바른 진단입니다.
7. **개선 방향**: 이 케이스를 PASS로 바꾸려면 코드가 아니라 데이터(필터 가중치)를 바꿔서 두 점수가 실제로 차이 나게 해야 합니다.

추가로 `test_error_data.json`으로 의도적 오류(행 수 불일치, 열 수 불일치, 숫자가 아닌 값, 알 수 없는 라벨, 필터 없음, 키 형식 오류, 0.1+0.2 vs 0.3 동점)를 넣어 실행했을 때, 프로그램이 멈추지 않고 9개 중 7개를 원인 메시지와 함께 FAIL 처리하는 것을 확인했습니다.

### 3-3. 성능 분석 (평균/10회)

> 수치는 한 번 실행한 예시입니다. 컴퓨터마다, 실행할 때마다 조금씩 달라집니다.

| 크기(NxN) | 평균 시간(ms) | 연산 횟수(N^2) | 1회 연산당 시간(ns) |
| --- | --- | --- | --- |
| 3x3 | 0.00075 | 9 | 약 83 |
| 5x5 | 0.00146 | 25 | 약 58 |
| 13x13 | 0.00738 | 169 | 약 44 |
| 25x25 | 0.02556 | 625 | 약 41 |

### 3-4. 시간 복잡도 분석: O(N^2)

1. MAC 함수는 행 N개 x 열 N개를 모두 방문하므로 곱셈과 덧셈이 정확히 N^2번 일어납니다. 그래서 시간 복잡도는 **O(N^2)** 입니다.
2. 측정값도 이를 뒷받침합니다. 13x13 → 25x25로 가면 연산 횟수가 169 → 625로 약 3.7배 늘고, 평균 시간도 0.00738 → 0.02556 ms로 약 3.5배 늘었습니다.
3. 3x3 → 25x25에서는 연산 횟수가 약 69배 늘었지만 시간은 약 34배만 늘었습니다. 크기가 작을 때는 함수 호출, 반복문 준비 같은 **고정 비용**이 상대적으로 크기 때문입니다.
4. 표의 "1회 연산당 시간"을 보면 크기가 커질수록 약 40 ns로 일정해집니다. 연산당 시간이 일정하다는 것은 전체 시간이 연산 횟수(N^2)에 비례한다는 뜻입니다.
5. N이 2배가 되면 시간은 약 4배가 됩니다. 실제 AI 모델은 수백x수백 크기 필터를 수천 개 쓰기 때문에, CPU처럼 하나씩 처리하면 매우 느립니다. 이것이 수천 개의 MAC을 동시에 처리하는 NPU가 필요한 이유입니다.
6. 측정은 10회 평균이라 실행할 때마다 조금씩 흔들릴 수 있습니다. 그래서 워밍업 1회를 먼저 실행하고, I/O를 빼고 연산 함수 호출 구간만 측정했습니다.

## 4. 보너스

### 4-1. 1차원 배열 최적화
- 2차원 리스트를 길이 N^2의 1차원 리스트로 펼치고(`flatten`), 반복문 하나로 MAC을 계산합니다(`mac_flat`).
- `pattern[i][j]`처럼 리스트를 두 번 찾아가던 접근이 `flat[k]` 한 번으로 줄어듭니다.
- 같은 입력, 같은 반복 횟수(10회)로 비교한 결과 (펼치는 시간은 측정에서 제외):

| 크기(NxN) | 2차원(ms) | 1차원(ms) |
| --- | --- | --- |
| 3x3 | 0.00059 | 0.00050 |
| 5x5 | 0.00144 | 0.00091 |
| 13x13 | 0.00737 | 0.00529 |
| 25x25 | 0.02656 | 0.02041 |

- 1차원 쪽이 약 15~37% 빨랐습니다. 다만 둘 다 반복 횟수는 N^2이므로 시간 복잡도는 똑같이 O(N^2)이고, 줄어든 것은 연산 1회당 드는 비용입니다.

  def mac(pattern, filt):
    n = len(pattern)
    total = 0.0
    for i in range(n):          # 행
        for j in range(n):      # 열
            total += pattern[i][j] * filt[i][j]
    return total
